### Completed

This phase documents existing behavior and adds no new hooks, tools, or capabilities; those choices are deferred for separate discussion.

Scores were assessed by this AI agent, not independently human-scored; one run is not statistical or comparative evidence. Raw run and report: `evals/coding/runs/f302ae7d-f1aa-42a0-a02f-a5b5b993d36b.json` and `docs/CODING_EVALUATION.md`. The focused fixture tests were executed separately because Bubblewrap is unavailable here, and the model could not run approved shell tests in Rook. Final local checks passed: lint, typecheck, 258 unit tests, 36 PTY tests, 7 integration tests, build, mock smoke, memory benchmark (100% precision/recall on 37 labeled retrieval prompts), FTS/reconciliation microbenchmark, coding-evaluation fixture verification, and package dry-run. Hosted Ubuntu/macOS/Windows CI remains unrun and requires a push.
- Harness parity roadmap Phase 4: added `rook_code`, a read-only coding-intelligence tool for TypeScript/JavaScript definition and reference navigation plus syntactic/semantic diagnostics for the selected file. It uses safe compiler settings from repository `tsconfig.json`, caps project files/results/output, filters sensitive/out-of-workspace files, and never writes. TypeScript 7 remains the project compiler; a pinned TypeScript 5.9 language service powers this integration because v7 exposes a different API surface.
- Harness parity roadmap Phase 3: `.rook/agents.json` defines bounded named subagent profiles and optional subsets of a fixed read-only tool allowlist. `/agents` lists and invokes profiles in fresh sessions; instructions are treated as untrusted guidance and cannot enable mutation, shell, MCP, or third-party extensions. Existing `/explore`, `/architect`, and `/review` workflows remain separately explicit. See README for the configuration shape.
- Harness parity roadmap Phase 2: Build-mode shell defaults to Bubblewrap isolation on Linux: system read-only, writable selected workspace only, private temporary/runtime paths, no network, and restricted user/PID namespaces. Routine allowlisted commands run without prompts; destructive and unclassified commands prompt, with exact-command/workspace session grants. Sandbox availability is probed at startup; absent/unusable runtime blocks shell before approval and never falls back to host. `.rook/policy.json` can explicitly opt out with `execution.sandbox_shell: false`, which is labeled in approvals. Added `rook worktree create|list|diff|remove` for managed detached independent clones under `.rook-worktrees/`; diff reviews against the recorded base commit, and removal refuses uncommitted or ignored content. Worktree isolation is for edits only, not a process sandbox. See README.
- Harness parity roadmap Phase 1: Rook now loads applicable `AGENTS.md` guidance from workspace root/current-directory ancestry and nested directories named in the user prompt. Reads are capped at four files, 8 KiB per file, and 12 KiB total; symlinks, outside paths, unreadable, empty, and oversized files are skipped. Guidance is XML-escaped, marked untrusted, and injected as hidden context without changing the system prompt or permission policy. `/instructions` lists loaded files. Other formats (including `CLAUDE.md`) are not loaded. See README and `docs/HARNESS_PRINCIPLES.md`.
- Harness parity roadmap Phase 0: added `npm run eval:coding` with four fixed, disposable offline tasks (repository exploration, bug fix, feature, review), separate trusted fixture checks, human-scored rubrics, validated JSON run records, and Markdown reports with answers and available run metrics. CI verifies the starter coding fixtures fail their checks. This is a reproducible scoring framework, not an automatic provider/model benchmark; model quality claims require repeated controlled runs and human grading. See `evals/coding/README.md`.
- ROOK-005: added the Rook app state/event reducer for lifecycle, run states, modes, streamed/final messages, tool activity, usage, errors, and shutdown. The headless CLI now uses it to gate prompts and track runs.
- Focused reducer tests cover startup/auth readiness, idle/running/settled/failed states, duplicate prompt/mode guards, authoritative final messages, tool/usage events, and shutdown.
- ROOK-006: added a custom `pi-tui` alternate-screen shell with a responsive header, home view, fixed multiline editor/footer, streaming Markdown, basic command handling, and terminal cleanup. Interactive tools were initially disabled pending ROOK-010.
- TUI visual choices follow `tui_references/SCREEN_SPEC.md` and `tokens.json`; the design reference files remain untouched.
- ROOK-007: mapped public Pi session events for streamed/final assistant text, usage, tool start/end, errors, and aborts. The TUI renders final text authoritatively and shows compact status-only tool rows; raw tool args/results are not exposed.
- ROOK-008: added Pi-backed model listing/selection, provider status/login/logout, and thinking-level settings. The TUI exposes `/model`, `/login`, `/logout`, and `/settings`; supported OAuth/API-key authentication runs through Pi's model runtime inside Rook, while model and thinking changes persist through Pi.
- ROOK-009: moved the Pi gateway onto `AgentSessionRuntime`, added `/new` and `/sessions`/`/resume`, and rebound session subscriptions/extensions after replacement. Session selection shows saved-session metadata; resuming restores user/assistant text while omitting tool arguments and results.
- ROOK-010: added a Pi `tool_call` boundary policy. `/plan` allows scoped workspace reads and file discovery; `/build` additionally allows scoped `edit`/`write`. Sensitive paths, symlink/hardlink paths, external extensions, and concurrent mutations are denied. Pi's grep uses ripgrep `--hidden`, so it stays disabled rather than risk reading hidden credentials. `/permissions` shows recent decisions and grants. The current Build shell policy allows routine sandboxed development commands without prompts and requires approval for destructive/unclassified shell commands and unclassified tools; see the current policy notes above.
- Security scope: most file-tool policy is host-side and does not sandbox concurrent processes. Shell commands are Bubblewrap-isolated on Linux by default, with no-network and workspace-only writes; unsupported hosts fail closed unless explicit host-shell opt-out is configured. Use an external container/VM for whole-session isolation.
- Terminal follow-up: `/build` enables Pi's `bash` tool behind the current sandboxed command policy; `/plan` blocks it and unattended execution fails closed for commands requiring approval. Rook enforces a 120s default / 300s maximum timeout and retains Pi output truncation/cancellation; see README terminal command safety notes.
- Code-quality and mode-aware execution policy: the Pi system prompt now receives code-first, simplicity, diff-review, and honest-verification guidance with project overrides in `.rook/policy.json`. Plan mode adds bounded `rook_search` for workspace text plus `rook_inspect`, a fixed-argument read-only Git status/diff/log/branch/file inspector (no arbitrary shell; sensitive paths filtered; Git optional index writes, pagers, hooks, and external configuration disabled). Build mode adds `rook_impact`, mapping actual changed paths to direct TypeScript dependents and related existing tests, recommending focused checks and escalating shared/high-impact or uncertain changes. Rook mechanically blocks recognized test/build/typecheck/lint Bash commands until impact analysis succeeds after the last Rook edit; command-name recognition is workflow sequencing, not shell security. Current MCP and unclassified-tool permission behavior is described in README and PI_PARITY.
- Workspace `models.json` providers merge into Pi's `ModelRuntime` through Pi's provider-registration API, preserving the Pi user catalog. `/model` refreshes workspace configuration each time it opens. Workspace API keys must be environment-variable references; literal credentials, command resolvers, non-HTTP(S) endpoints, and URLs containing userinfo are rejected. Runtime model fields receive Pi-compatible defaults before provider registration; a mocked stream regression verifies requests get through model compatibility handling.
- ROOK-011: added Git and non-Git workspace identity in a locked, atomic, permission-restricted `~/.rook/repositories.json` registry (`ROOK_HOME` overrides the directory). Git working trees get generated IDs keyed by local Git metadata identity, so clones stay distinct and worktrees get distinct IDs with a common logical ID; path renames retain the ID. Credential-free remote fingerprints are hashed before storage. The registry retains the latest branch/HEAD/dirty snapshot, and the TUI displays the repository ID and initial snapshot. SQLite/history remains ROOK-012.
- ROOK-012: added `better-sqlite3` (Node 22.19+ verified) and transactional, versioned SQLite migrations with WAL, foreign keys, constraints, indexes, FTS5 triggers, and a rebuild operation. Real workspaces now persist generated repository identity and append snapshot history to `~/.rook/state.sqlite`; the ROOK-011 JSON registry remains the identity resolver. Added parameterized memory persistence/search, content-clearing soft delete and purge, SQLite backup, and JSON export. The database is created with owner-only file permissions.
- ROOK-013: added repo-scoped memory create/get/list, source evidence management, revision history for edits, pinning, semantic-key deduplication with evidence dedupe, and explicit forget with cascading physical removal from the live database. Secret-like content and secret-bearing file paths are rejected before persistence; soft-deleted content is removed from FTS and copied text is cleared from revision/evidence records.
- ROOK-014: added repo-scoped, query-dependent retrieval with exact repository scoping, verified/trusted/evidence-backed filters, lexical/FTS/path/symbol/source/recency/freshness ranking, and a top-K context composer capped at 1,500 estimated tokens. Context is XML-escaped and explicitly untrusted; stale memories are labeled historical, and irrelevant queries inject nothing. The Pi SDK's documented `before_agent_start` hook receives context as a hidden custom message without rewriting the system prompt. Retrieval logs persist only memory IDs and token estimates, never prompt or memory content.
- ROOK-015: added bounded deterministic capture on Pi `agent_settled` for high-signal user decisions/conventions/fix statements with successful read/edit/write evidence. Capture revalidates workspace boundaries, rejects sensitive paths, hashes at most three small files without persisting their contents, and creates non-retrievable candidates. `remember:` requests are persisted as pending claims and require `/memory confirm <id>`; `/memory cancel`, `/memory pause|resume`, project `/memory opt-out|opt-in`, `/memory show`, and confirmed `/memory forget` controls are available. Capture is capped at three records per session, has no LLM extraction, and project opt-out suppresses both capture and retrieval.
- ROOK-016: added safe on-demand evidence hashing and reconciliation at startup, before memory retrieval, and `/memory refresh`. Changed/missing/unsafe evidence marks a memory stale with a revision before it can be retrieved; matching hashes across commits/branches add fresh provenance. Commit-only claims are invalidated after a snapshot change. Renames that cannot be re-linked are conservatively stale. Manual verification refreshes evidence and creates a user-attributed revision.
- ROOK-017: `/memory status` reports totals by status; `/memory show` lists repository-scoped records; `/memory detail <id>` shows claim, provenance, evidence hashes/paths, and validity; `/memory verify <id>` rechecks current files; `/memory forget <id> confirm` is repository-scoped. Existing pause, opt-out, and explicit-confirmation controls remain available.
- ROOK-018: added `npm run benchmark:memory`, a deterministic offline retrieval comparison across three isolated repository fixtures and 37 prompts against an empty-memory baseline. `docs/BENCHMARKS.md` is generated by the harness and reports fixture-level precision/recall, false retrievals, context tokens, and limitations; no provider calls are required.
- ROOK-019 local hardening: retrieval now uses normalized whole-word overlap, abstains on generic-only and explicitly other-repository queries, and restricts historical questions to uncertain historical leads. The benchmark now reports 100% precision/recall with zero false retrievals on its labeled 37-prompt set. Added real temporary-Git tests for branch changes, dirty edits, renames, and preservation of user-confirmed decisions; added cross-repo and untrusted-context regressions.
- ROOK-019 release checks: CI now covers Ubuntu/macOS/Windows on Node 22.19 and runs lint, unit/PTY/integration tests, build, mock smoke, both benchmarks, and package dry-run. Added package allowlisting and `prepack` build so the tarball contains `bin` + `dist` but excludes local references/tests, corrected README usage, and added Pi MIT notices. `npm pack --dry-run` verified the package contents.
